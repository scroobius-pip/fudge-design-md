# How ami.dev is designed

[Open the live Fudge conversation](https://design.withfudge.com/share/ami.dev-design)

Last updated: 2026-07-28

## Design character

ami.dev is a **typographic personal/developer site**: cream or soft paper ground, black grotesk headlines at confident sizes, and almost no decorative system beyond text, links, and spacing. It feels closer to a carefully set résumé-essay hybrid than a product landing page. Personality comes from writing and hierarchy, not illustration kits.

What should survive adaptation:
- Light warm canvas and black ink
- Large, honest headlines
- Single-column reading measure
- Link-led navigation instead of heavy component chrome

## Foundations

### Color

No stable measured palette roles were retained across these pages; rely on the visual description. Visually monochrome on cream/off-white. Links may use a default emphasis color, but the brand does not depend on a loud primary. Keep contrast high for body text.

Hierarchy is everything: big name or page title, medium section labels, comfortable body. Monospace may appear for code identity, but the captures emphasize clean proportional type. Avoid fashion-thin weights that undermine readability.

### Spacing and layout

Recurring spacing measurements include -600px, -40px, 4px, 8px, 10px, 12px, 15px, 16px, 20px, 24px, 32px, 40px, 112.75px. Long vertical scroll with generous section gaps. Content width stays narrow enough to read. Observed corner radii include 4px, 7px, 8px, 11px, 12px, 16px, 3.35544e+07px. Cards are optional; many blocks can be plain stacked text.

## Visual language

Flat, minimal, slightly editorial. Borders only when lists or projects need separation. No heavy shadows. If projects are shown, simple title + one-liner beats thumbnail carnival.

## Components and states

- Text header with name/mark and a few links
- Hero identity line
- Project or writing lists
- Footer with basic contact links

## Responsive behavior

Widths from ~1680–1712px down to shorter crops still keep a single column. Maintain margin growth on large screens rather than stretching lines endlessly.

## Practical guidance

**Preserve**
- Paper/cream calm and typographic confidence
- Sparse nav and reading-first layout

**Avoid**
- Fake SaaS dashboards on a personal site
- Gradient hero theatrics
- Over-componentized cards for simple links
