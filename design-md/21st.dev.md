## Overview

21st.dev uses a dark catalog grammar with a product-tool feel. The page hierarchy is built from a nearly black shell, thin grid lines, compact labels, and a large number of framed previews. It reads less like a marketing site and more like a workstation for browsing, filtering, and opening UI assets.

The strongest visual trait is density without clutter. Left navigation, top bars, tab rows, metrics, and large preview tiles all sit on the same dark field, but each area stays legible because spacing is precise and borders are consistent. Blue is the only strong action color. Mint appears as a rarer highlight. White surfaces appear inside preview cards and source panels, giving the page a sharp light/dark contrast while keeping the outer shell stable.

The design should feel:
- Dark, controlled, and catalog-like.
- Compact rather than roomy.
- Framed by 1px rules and small radii.
- Driven by blue actions and mint accents.
- Comfortable mixing black panels, white preview surfaces, and pastel demo art in one view.

## Colors

The interface colors are sparse and disciplined. `#09090B` and `#101010` carry most of the shell, while `#171717` and `#191919` separate nested panels, cards, and selected strips. `#27272A` is the structural border color; it keeps the grid visible without turning the page into a boxed spreadsheet. Text stays bright with `#F4F4F5` on the dark shell, then softens to `#8F8F99` for counts, helper text, and secondary metadata.

The primary interaction color is `#0033FF`. It is used for the most important button states and for any control that should pull the eye immediately. `#99FFE4` is a secondary accent that belongs to small highlights, active indicators, or decorative emphasis. `#FFC799` works as a warm counterpoint inside bright preview art and should stay rare. `#FFFFFF` is the relief color: it appears in prompt canvases, content cards, and source views, not as the default shell.

The page works because these roles are distinct. The shell stays dark. The text stays light. The accent colors are selective. That gives the grid room to carry a lot of content without flattening into noise. The bright cards and light canvases are not separate themes; they are controlled interruptions inside the same dark system.

| token | value | role |
|---|---|---|
| `canvas` | `#09090B` | Main page ground and sidebar ground |
| `surface` | `#101010` | Default card and panel fill |
| `surface-raised` | `#171717` | Secondary containers and active strips |
| `surface-strong` | `#191919` | Higher-contrast nested areas |
| `border` | `#27272A` | Grid lines, dividers, card frames |
| `ink` | `#F4F4F5` | Main text on dark surfaces |
| `muted-ink` | `#8F8F99` | Counts, helper text, quiet metadata |
| `action` | `#0033FF` | Primary buttons and selected actions |
| `accent` | `#99FFE4` | Rare highlights and active accents |
| `highlight` | `#FFC799` | Warm glow inside bright preview art |
| `inverse` | `#FFFFFF` | White cards, source panes, and reversed text |

## Typography

The system is built on **Abc Diatype Unlicensed** for almost all interface text, with **Geist Mono** for code and **Geist** for compact utility surfaces. Licensing details for these fonts are not supplied. The feel is crisp, modern, and compact; the site relies on size steps and weight shifts more than on many typographic families.

Type is small enough to keep the catalog dense, but not so small that it becomes brittle. Main headings sit around 20px, prominent card titles around 15px, body copy around 14–16px, and meta text around 11–12px. Weight changes carry meaning: 400 for general copy, 500 for controls and stronger labels, 600 for short headings. Tracking is mostly neutral, with a little negative tightening on titles and a more open feel on compact labels.

| token | family | size | weight | leading | tracking | use |
|---|---|---:|---:|---:|---:|---|
| `page-title` | Abc Diatype Unlicensed | 1.25rem | 600 | 1.4 | -0.025em | Page and studio headings |
| `section-title` | Abc Diatype Unlicensed | 1rem | 500 | 1.4 | -0.015em | Section headers and short labels |
| `card-title` | Abc Diatype Unlicensed | 0.9375rem | 600 | 1.45 | -0.01em | Tile titles and feature names |
| `body` | Abc Diatype Unlicensed | 1rem | 400 | 1.5 | 0em | Supporting copy and descriptions |
| `body-strong` | Abc Diatype Unlicensed | 0.875rem | 500 | 1.45 | -0.005em | Buttons, selected items, key values |

## Layout

The layout is a desktop app layout, not a classic editorial page. A fixed left rail holds the product taxonomy, search, and category counts. The main area begins with a thin top bar and then opens into rows of cards. In some screens the main area is a wide gallery of previews; in others it becomes a studio dashboard with metrics, tabs, search, and a table. The same grid logic keeps returning, so the experience feels coherent even when the content changes.

This system depends on alignment. The rail, section headers, and card edges line up on a strict grid. Cards use consistent border color and similar corner treatment, so the eye can scan across rows without re-learning the page. The content density is high, but the page avoids visual pileup by separating clusters with full-width gutters and by using large card fields rather than many tiny widgets.

The most important spatial traits are:
- A narrow rail beside a wide content field.
- Repeated card widths across rows.
- Small inner padding inside cards, with more generous gutters between groups.
- A clear distinction between shell, nested panel, and content surface.
- A steady rhythm of section header, grid, then secondary controls.

Section breaks matter more than decorative separators. The page uses dark background continuity, then inserts card rows, tab rows, and metric strips as functional breaks. On the studio view, empty-state cards and the table area make the page feel like a workspace. On the gallery views, the large preview tiles make it feel like a component library. The visual structure stays simple enough that the many thumbnails and labels do not compete with the navigation or the current section title.

The layout also leans on fixed-width rails and a predictable content spine. That keeps the left side steady while the content pane changes from gallery to studio to detail view. The result is a dashboard that feels designed for scanning first, then opening one item at a time.

## Visual language

The visual language is geometric, compact, and slightly technical. Rounded rectangles dominate. Borders are thin. Shadows are minimal. The visual weight comes from contrast between deep black shells and bright preview surfaces, not from depth effects. When the page needs emphasis, it uses a blue button, a brighter tile, or a white panel rather than a large shadow or a loud gradient.

The previews do a lot of the expressive work. Some are pure dark canvases with a centered widget. Some are white cards with a small interactive control. Some are bright image-like panels with pastel or saturated color. That variety gives the library a lively center while the shell remains disciplined. The system can hold a colorful demo card next to a monochrome source panel because the frame language is consistent.

Keep the language restrained:
- Thin borders instead of heavy outlines.
- Small radii instead of soft consumer curves.
- Dark surfaces instead of tinted backgrounds.
- Blue for decisive action, mint for rare highlights.
- White only when a surface needs to break the dark field.

The mood is that of a builder’s workspace: efficient, polished, and slightly austere. It should feel organized before it feels decorative. The page never needs large decorative ornaments because the hierarchy already comes from contrast, spacing, and repetition.

## Components

### App shell and top bar

The shell is a full-viewport dark workspace with a minimal top bar. The top row carries a product label, centered page title on some screens, and lightweight utility actions. The bar does not dominate the page; it simply sets the context for the content below. Keep it thin and quiet, with small text and clear separation from the main field. The main impression should come from the content grid, not from chrome.

### Left navigation rail

The rail is one of the most distinctive parts of the system. It stacks a logo, search, top-level navigation, section labels, and long category lists with counts. Rows are compact and easy to scan. The active row uses a darker filled state inside the already-dark shell, so selection reads through tone rather than through bright color. The icon set stays simple and monochrome. The rail should feel dense but not crowded, with enough vertical rhythm that the long category list remains readable.

### Card grid and preview tiles

The gallery cards are the backbone of the interface. They use a dark fill, 1px border, and small radius, then place the preview or thumbnail inside with enough inset space to let the content breathe. Some tiles are white and minimal; others are black with a single vivid UI object centered in them; others show colorful component art. Titles and small meta lines sit below or alongside the preview. These cards should remain highly regular so the page can scale to many items without losing order. Variation belongs in the preview content, not in the container system.

### Studio metrics and table area

The studio view adds dashboard structure without changing the visual language. Small metric cards line up across the top, each with a quiet label and a zero or empty-state value. A bright blue action button appears near the search field. Below that, tab pills switch between published, review, and draft states, and a table header anchors the lower section. Empty states are plain and centered. The key is restraint: the dashboard should look functional, not celebratory. The table and metrics should feel like a control surface attached to the same catalog system.

### Prompt box and code split view

The prompt-box demo uses a split composition: a code panel on the left in **Geist Mono**, and a large pastel canvas on the right with a floating input capsule. The right side uses a soft gradient field with a warm glow that shifts from lavender to pink to orange. The input itself is dark, rounded, and centered. This contrast makes the demo feel more experimental than the rest of the site while still staying inside the same design system. The split view is the clearest place where the system allows atmosphere without losing control.

### Buttons, tabs, and small controls

Primary buttons are compact blue pills with white text and a strong presence. Secondary controls are darker and quieter. Tab pills use a filled active state and a softer inactive state. Icon-only controls are tiny, circular, or slightly rounded and remain visually lightweight. Their job is to reduce friction without stealing attention from the card grid. Wherever possible, these controls should inherit the same border, radius, and text scale used by the rest of the workspace so the interface feels continuous.

## Responsive behavior

On smaller screens, the rail should collapse before the grid loses its rhythm. The content order should stay predictable: shell, navigation, section header, content tiles, then secondary controls. Cards should stack into fewer columns while keeping the same border, radius, and spacing logic. Tab rows and search controls need to remain compact rather than wrapping into tall blocks. The prompt-box split should become a vertical stack, with the code panel above or below the canvas, not side by side. The overall rule is simple: preserve density, reduce columns, and keep the card language intact. The interface can get narrower, but it should not become looser or more decorative.

## Practical implementation guidance

### Preserve

- Keep the shell near-black and the text bright.
- Use blue as the main action color and mint as a rare secondary accent.
- Retain the 1px border grid and the small 3–10px corner range.
- Let the left rail stay compact and information-rich.
- Keep code in **Geist Mono** and the main UI in **Abc Diatype Unlicensed**.
- Preserve the contrast between dark shell, white panels, and colored preview art.

### Avoid

- Avoid soft consumer gradients across the whole page.
- Avoid large shadows or glass effects.
- Avoid oversized radii or pill shapes everywhere.
- Avoid making every card a different color or border treatment.
- Avoid widening the layout so much that the rail and content field stop feeling related.
- Avoid introducing motion-heavy states that are not shown in the page surfaces here.

### Recommended build order

1. Build the shell, top bar, and left rail.
2. Establish the card frame and border system.
3. Add the preview grid with a few consistent tile variants.
4. Layer in tabs, search, and compact controls.
5. Build the studio metric cards and table structure.
6. Add the split code/demo view with the bright canvas.
7. Tune spacing so the page keeps its dense rhythm on wider screens.

### Accessibility

- Keep text contrast high on the dark shell and on white preview cards.
- Give selected rows and active tabs a non-color cue through fill, weight, or border treatment.
- Maintain readable line lengths in long descriptions and table cells.
- Keep keyboard focus visible on every clickable control.
- Make icon buttons large enough to tap while staying visually small.
- Do not rely on color alone to explain active, selected, or empty states.

## Scope note

This guide covers the desktop home, featured, studio, and component-detail surfaces shown here. Smaller screens, motion, hover and keyboard states, exact icon sets, and unshown empty, loading, or error variations are outside scope. Spacing and corner values are rounded to the nearest packet step.
