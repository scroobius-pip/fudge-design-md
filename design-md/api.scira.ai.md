# How api.scira.ai is designed

[Open the live Fudge conversation](https://design.withfudge.com/share/api.scira.ai-design)

Last updated: 2026-07-28

## Design character

Scira’s API marketing presents as a **modern AI developer landing**: strong hero headline, product/API emphasis, and a contemporary startup composition that prioritizes trying or understanding the API quickly. Captures are primarily home views at multiple widths—use them as a marketing system, not a full console design.

What should survive adaptation:
- Clear hero promise with concise supporting copy
- Developer-credible layout (code or product visuals near the fold when present)
- Simple top nav and obvious primary CTA
- Restrained accent usage against a clean ground matching the captured home

## Foundations

### Color

No stable measured palette roles were retained across these pages; rely on the visual description. Lean on screenshot judgment: keep contrast high for hero type; accents should mark CTAs and links only. Do not invent a multi-stop brand gradient unless visibly dominant.

### Typography

Declared type families were not retained; hierarchy is described from the screenshots.

Large marketing sans for heroes; smaller body; possible mono for API snippets. Keep hierarchy steep on the landing page.

### Spacing and layout

Spacing is better read from layout rhythm in screenshots than from a full token table. Wide heroes and section bands with comfortable vertical rhythm; multi-width homes show how margins grow. Observed corner radii include 16px, 24px, 1.67772e+07px.

## Visual language

Contemporary AI-startup minimalism: soft cards or code panels, modest radii, limited ornament. Prefer product truth over abstract 3D toys.

## Components and states

- Header with wordmark, docs/pricing links, CTA
- Hero stack
- Feature or API capability rows
- Code/sample modules when shown
- Footer links

## Responsive behavior

Homes from ~1425–2018px widths: type scales, sections stack, CTAs remain thumb-friendly. Keep the hero message intact when images stack.

## Practical guidance

**Preserve** developer clarity, strong hero hierarchy, simple CTA path.  
**Avoid** cluttering the landing with dashboard density or unverified font theatrics.

## Scope note

Studied 5 page captures on paths /. Some structural families were incomplete on these pages. Home captures only across widths; authenticated API console was not in the set.
